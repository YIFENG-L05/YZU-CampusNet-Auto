## 本版要点

### Android

- **移动数据下也能自动连上校园 Wi-Fi**：只要开着 Wi-Fi 开关、权限齐全、填了校园 Wi-Fi 的**精确 SSID**、且当前没连着别的 Wi-Fi，
  应用会在使用移动数据时向 Android 系统**建议**连接校园 Wi-Fi（Android 10+ 的建议机制）。
  连上之后才进入认证链路（门户探测 → 统一身份认证 → 服务绑定 → 确认联网）。
  已经连着别的 Wi-Fi 时会**撤回**建议；你关掉 Wi-Fi 开关时它什么都不做，也不会替你打开 Wi-Fi。
- **首次启动说明**：只在第一次打开时出现，正文必须读到末尾才能点「我已阅读并继续」。
  读不完就点不动，返回键只会把应用退到后台，不会算作已读。
- 设置里新增「关于」；「运行准备度」里能看到「校园 Wi-Fi 自动连接」的当前状态。

### 文档（与实现逐条对齐）

- 「使用规则」：自动连接逻辑 / 自动认证逻辑 / Wi-Fi 切换规则 / Android 系统限制 / 校园网兼容性 / 排查步骤，共六节。
- 「隐私声明」：15 节，明确区分「CampusNet 自己的处理（无服务器、不上传）」与「你与学校认证系统之间的通信」。
- 「第三方 SDK 公示」「开源软件声明」：按实际构建依赖与许可证逐个核对，未声明许可证的组件如实标注。
- 仓库根目录新增 `THIRD-PARTY-NOTICES.md`。

### 修复

- 首次启动说明的"读完才能继续"判定加固（瞬态布局下可能被误放行的竞态）。
- 校园 Wi-Fi 发现链路四个真机缺陷：读不到 SSID 的瞬态会撤回刚提交的建议；进程重启后内存里的建议集合为空；
  运行准备度长文本把标签列挤成 0 宽；发现心跳与 Core 定时器共用同一线程。

## 认证兼容性（请仔细读）

**已验证**：Ruijie ePortal（门户拦截 → 302/JS 跳转）+ CAS / 统一身份认证 SSO + 服务选择/绑定
—— 在真实校园网 `YZU-WLAN` 上完成验证（Windows 与 Android 均实测）。

**暂未适配或未验证**：Srun / 深澜、Dr.COM、其他校园网认证平台，以及与当前 CAS SSO 流程不同的锐捷部署方式。

不同学校即使使用同一厂商的产品，认证页面、SSO 参数、加密方式与服务选择流程也可能不同，
因此**不保证**在其他学校可以直接使用。

## 已知限制

- 校园 Wi-Fi 只能向系统"**建议**"连接：Android 没有强制连接/强制切换 Wi-Fi 的公开接口，无法保证必然连上；
  应用也不会替你打开已经关闭的 Wi-Fi。
- 需要口令（加密）的校园 Wi-Fi **不支持**。
- 校园 Wi-Fi 规则当前只对**精确 SSID** 生效；前缀 / 正则规则不会自动请求连接（界面会说明原因）。
- 只验证了 Ruijie ePortal + CAS SSO 这一类链路；Srun / 深澜、Dr.COM 等**暂未适配**。
- 学校调整门户/SSO 页面后可能失效，需要重新抓取并更新协议实现。
- Android 各 OEM 的后台/自启动限制不同，未加白名单时可能被杀；部分系统开关**没有公开查询接口**，只能用户自行确认。
- Android 只有 debug 签名；Windows 安装包未签名。
- 不绕过验证码、账号限制或门户故障，遇到时如实报失败并按退避重试或停手。

## 安装

**Windows**：下载 `CampusNet-Setup-1.0.1.exe` → 双击 → 选择安装目录（默认用户目录，不需要管理员权限）→
完成后在界面里填写**校园网账号 / 密码 / 运营商**，建议勾选「开机自动启动」。

**Android**：下载 `CampusNet-Android-v1.0.1-debug.apk` → 允许安装未知来源应用 → 安装 →
打开后先读完首次启动说明，再按提示授予必要权限（附近的 Wi-Fi 设备、位置信息、通知）→
在「设置 → 账号与认证」填写账号密码 → 在「设置 → 运行准备度」确认必需项都满足。

> 卸载时请用应用内的卸载入口（Windows），它会一并清理开机启动项与本地凭据。
